# 字符串算法：KMP、哈希、Trie 与 AC 自动机

> 定位：字符串题看起来简单，真正拉开差距的是「匹配」：朴素匹配 O(nm) 在大文本上不可接受，KMP 用前缀函数做到 O(n+m)，滚动哈希用概率换常数，Trie/AC 自动机解决多模式匹配。这一篇从字符串的底层表示讲起，逐层给出模板、证明直觉、碰撞处理与工程边界。

## 一、字符串的底层：不可变与编码

### 1.1 String 为什么不可变

`String` 内部用 `final` 字段存字符数据，所有「修改」都返回新对象。不可变带来：

- 可以安全地作为 HashMap 的 key（hash 可缓存）；
- 可以共享常量池中的实例；
- 多线程读取天然安全；
- 但循环拼接会产生大量临时对象。

### 1.2 JDK 9+ 的紧凑字符串

JDK 9 起 `String` 用 `byte[] value` + `byte coder`：

- 纯 Latin-1 字符用 1 字节/字符；
- 含中文等非 Latin-1 用 UTF-16，2 字节/字符；
- `coder` 标记编码方式。

这让英文为主的字符串内存占用减半，但 `charAt` 需要按 coder 解码。

### 1.3 拼接与 Builder

```java
StringBuilder sb = new StringBuilder();
for (String s : list) sb.append(s).append(',');
String result = sb.toString();
```

循环里 `s += x` 每次创建新 String，复杂度 O(n²)；`StringBuilder` 是 O(n)。JDK 9+ 对简单拼接用 `invokedynamic` 优化，但循环里仍建议显式 Builder。

### 1.4 字符与字节

- `char` 是 UTF-16 码元，不是「一个 Unicode 字符」；
- emoji/生僻字可能占两个 char（代理对）；
- 按字节处理用 `byte[]` + `Charset`；
- 比较/排序注意 Unicode 规范化（NFC/NFD）。

工程坑：用 `length()` 判断「字符数」在 emoji 场景会错，要用 `codePointCount`。

## 二、朴素匹配：为什么慢

```java
int naive(String s, String p) {
    for (int i = 0; i + p.length() <= s.length(); i++) {
        int j = 0;
        while (j < p.length() && s.charAt(i + j) == p.charAt(j)) j++;
        if (j == p.length()) return i;
    }
    return -1;
}
```

最坏 O(nm)：例如 `s = "aaaa...aab"`，`p = "aaaa...a"`，每次都在最后一位失败，前面比较全部浪费。

## 三、KMP：用前缀函数复用比较

### 3.1 核心思想

当 `s[i]` 与 `p[j]` 失配时，朴素算法回退到 `i+1`；KMP 利用「已经匹配的部分」的信息，把模式串回退到 `next[j-1]`，主串指针不回退。

`next[i]` 表示 `p[0..i]` 的**最长相等真前缀与真后缀**的长度。

### 3.2 前缀函数

```java
int[] prefixFunction(String p) {
    int m = p.length();
    int[] next = new int[m];
    for (int i = 1, j = 0; i < m; i++) {
        while (j > 0 && p.charAt(i) != p.charAt(j)) {
            j = next[j - 1];
        }
        if (p.charAt(i) == p.charAt(j)) j++;
        next[i] = j;
    }
    return next;
}
```

例：`p = "ababaca"`，`next = [0,0,1,2,3,0,1]`。

### 3.3 匹配

```java
int kmp(String s, String p) {
    if (p.isEmpty()) return 0;
    int[] next = prefixFunction(p);
    for (int i = 0, j = 0; i < s.length(); i++) {
        while (j > 0 && s.charAt(i) != p.charAt(j)) {
            j = next[j - 1];
        }
        if (s.charAt(i) == p.charAt(j)) j++;
        if (j == p.length()) return i - p.length() + 1;
    }
    return -1;
}
```

复杂度 O(n+m)。关键在于：`j` 只增不减地回退，且每次回退都减少已匹配长度，总回退次数 O(n)。

### 3.4 为什么 next 能复用

失配时，`p[0..j-1]` 已经和主串匹配；如果 `p[0..j-1]` 有一个长度为 k 的相等前后缀，那么主串对应的后缀也等于 `p[0..k-1]`，可以直接从 k 继续比较，不需要回退主串。

### 3.5 KMP 的常见用法

- 查找子串；
- 判断周期：`n % (n - next[n-1]) == 0` 时，最小周期 = `n - next[n-1]`；
- 统计所有出现位置：匹配成功后 `j = next[j-1]` 继续；
- 最短循环节、重复子串。

### 3.6 KMP 的边界

- 空模式串要特判；
- 字符数组 vs String 的索引；
- `next` 数组只与模式串有关，可预处理复用；
- 中文/Unicode 用 `char` 比较可能出现代理对问题，按 code point 处理更稳。

## 四、滚动哈希：用概率换常数

### 4.1 多项式哈希

把字符串看作 base 进制数：

```text
H(s) = (s[0]*base^(n-1) + s[1]*base^(n-2) + ... + s[n-1]) mod M
```

预处理前缀哈希与 base 的幂，子串哈希 O(1)：

```text
hash(l, r) = H[r+1] - H[l] * base^(r-l+1) mod M
```

### 4.2 代码

```java
class RollingHash {
    private final long[] h, pow;
    private final long base = 131, mod = 1_000_000_007L;

    RollingHash(String s) {
        int n = s.length();
        h = new long[n + 1];
        pow = new long[n + 1];
        pow[0] = 1;
        for (int i = 0; i < n; i++) {
            h[i + 1] = (h[i] * base + s.charAt(i)) % mod;
            pow[i + 1] = pow[i] * base % mod;
        }
    }

    long hash(int l, int r) { // [l, r]
        long v = (h[r + 1] - h[l] * pow[r - l + 1]) % mod;
        return v < 0 ? v + mod : v;
    }
}
```

### 4.3 碰撞与对策

单哈希可能碰撞。工程上：

- 用双哈希（两个 base/mod）；
- 用随机 base；
- 哈希相等后再逐字符校验（最稳）；
- 对抗性输入下不要用固定 base。

### 4.4 典型应用

- 子串相等判断；
- 最长重复子串（二分长度 + 哈希集合）；
- 回文判断（正反哈希）；
- 大文本 diff 的快速预筛；
- 数据库/缓存 key 的指纹。

## 五、Trie 与 AC 自动机：多模式匹配

### 5.1 Trie 回顾

Trie 的插入/查询 O(L)，适合：

- 前缀查询/自动补全；
- 敏感词过滤；
- IP 路由最长前缀匹配；
- 单词词典。

### 5.2 AC 自动机

AC 自动机 = Trie + fail 指针。fail 指针指向「当前前缀的最长后缀，且是某个模式的前缀」。

构建：

1. 把所有模式插入 Trie；
2. BFS 构建 fail：根的子节点 fail = root；其他节点 `fail = parent.fail.next[c]`，不存在则继续跳 fail；
3. 匹配时沿 fail 跳转，统计命中。

```java
class ACAutomaton {
    static class Node {
        Node[] next = new Node[26];
        Node fail;
        int len; // 以该节点结尾的模式长度，0 表示不是结尾
    }

    private final Node root = new Node();

    void insert(String p) {
        Node cur = root;
        for (char c : p.toCharArray()) {
            int i = c - 'a';
            if (cur.next[i] == null) cur.next[i] = new Node();
            cur = cur.next[i];
        }
        cur.len = p.length();
    }

    void build() {
        Queue<Node> q = new ArrayDeque<>();
        for (int i = 0; i < 26; i++) {
            if (root.next[i] != null) {
                root.next[i].fail = root;
                q.offer(root.next[i]);
            } else {
                root.next[i] = root; // 便于匹配时直接跳
            }
        }
        while (!q.isEmpty()) {
            Node cur = q.poll();
            for (int i = 0; i < 26; i++) {
                Node child = cur.next[i];
                if (child != null) {
                    child.fail = cur.fail.next[i];
                    q.offer(child);
                } else {
                    cur.next[i] = cur.fail.next[i];
                }
            }
        }
    }

    boolean matches(String s) {
        Node cur = root;
        for (char c : s.toCharArray()) {
            cur = cur.next[c - 'a'];
            if (cur.len > 0) return true;
        }
        return false;
    }
}
```

复杂度：构建 O(total length × alphabet)，匹配 O(n + 命中数)。敏感词场景可在节点存输出链表，匹配时输出所有命中模式。

### 5.3 Trie/AC 的工程边界

- 字符集大时 26 叉数组浪费内存，用 Map；
- 中文敏感词按字符/词粒度分词，不能只按 26 字母；
- AC 自动机的 fail 指针构建要 BFS，不能 DFS；
- 动态增删模式需要重建或增量更新。

## 六、Manacher：最长回文 O(n)

### 6.1 核心思想

回文分奇偶长度，统一用分隔符处理：`abc` → `^#a#b#c#$`。每个位置维护回文半径 `p[i]`，利用已知回文的对称性复用半径。

### 6.2 模板

```java
int longestPalindrome(String s) {
    StringBuilder sb = new StringBuilder("^#");
    for (char c : s.toCharArray()) sb.append(c).append('#');
    sb.append('$');
    String t = sb.toString();
    int n = t.length();
    int[] p = new int[n];
    int center = 0, right = 0, best = 0;
    for (int i = 1; i < n - 1; i++) {
        int mirror = 2 * center - i;
        if (i < right) p[i] = Math.min(right - i, p[mirror]);
        while (t.charAt(i + p[i] + 1) == t.charAt(i - p[i] - 1)) p[i]++;
        if (i + p[i] > right) {
            center = i;
            right = i + p[i];
        }
        best = Math.max(best, p[i]);
    }
    return best;
}
```

`best` 就是原串最长回文长度（分隔符不计入半径）。

### 6.3 适用与边界

- 只求长度很优雅；要输出具体回文要额外记录中心；
- 字符集任意，但分隔符不能出现在原串；
- 代码下标多，建议用哨兵 `^`/`$` 防越界；
- 工程里若只判回文，双指针 O(n) 更简单。

## 七、正则与工程字符串处理

### 7.1 正则的回溯风险

`(a+)+b` 这类嵌套量词在长串上可能 catastrophic backtracking，复杂度指数级。对策：

- 避免嵌套量词；
- 用占有量词/原子组；
- 限制输入长度；
- 高风险场景用确定性解析器。

### 7.2 编码与规范化

- 外部输入统一 UTF-8；
- 比较前做 Unicode 规范化；
- 大小写转换用 `Locale.ROOT`，避免土耳其 i 问题；
- 按 code point 遍历，不要按 char 假设「一个字符」。

### 7.3 大文本处理

- 流式读取，避免全量加载；
- 分行/分块处理；
- 用 `StringBuilder` 控制内存；
- 大文件匹配用多模式 AC 自动机，不要逐模式跑 KMP。

## 八、字符串题型地图

| 题型 | 方法 | 关键 |
|---|---|---|
| 最长无重复子串 | 滑动窗口 | 左指针跳重复位置 |
| 最长回文 | 中心扩展/Manacher | 奇偶统一 |
| 子串查找 | KMP | next 数组 |
| 重复子串 | 后缀数组/哈希 | 周期判定 |
| 字符串相加/相乘 | 模拟 | 进位 |
| 编辑距离 | DP | 三方向转移 |
| 单词拆分 | DP/Trie | 字典匹配 |
| 前缀/自动补全 | Trie | 节点结束标记 |
| 多模式敏感词 | AC 自动机 | fail 指针 |
| 大文本相等 | 滚动哈希 | 双哈希 + 校验 |

面试时先判断「是单模式还是多模式」「要不要精确」「文本多大」，再选结构。

## 九、工程案例：敏感词过滤

### 9.1 需求

给定数万个敏感词，实时过滤用户输入，要求：

- 单次匹配不能遍历所有词；
- 支持中文；
- 能输出命中的词与位置；
- 可动态更新词库。

### 9.2 方案

1. 构建 Trie/AC 自动机，O(total length)；
2. 匹配时从每个位置沿 fail 跳转，O(n + 命中数)；
3. 节点存 `output` 链表，记录以该节点结尾的所有模式；
4. 词库更新：重建（简单）或增量更新（复杂）；
5. 中文按字符/词粒度，注意全角/半角、繁简、大小写归一化。

### 9.3 边界

- 敏感词含空格/标点，要先归一化；
- 长文本要限制单次处理长度，避免阻塞；
- 误杀/漏杀要有人工审核与白名单；
- AC 自动机的 fail 构建必须 BFS。

## 十、工程案例：大文本去重

### 10.1 方案

- 计算每行/每段的滚动哈希；
- 按哈希分桶到多个文件；
- 桶内用「哈希 + 原文」精确去重；
- 双哈希降低碰撞，原文校验兜底。

### 10.2 为什么不用 KMP

KMP 是「一个模式在文本中查找」，不是「海量文本两两比较」。去重是哈希/分桶问题，不是匹配问题。选错工具，复杂度会爆炸。

## 面试高频问法

**Q1：KMP 的 next 数组表示什么？**

一句话结论：`next[i]` 是模式串 `p[0..i]` 的最长相等真前缀与真后缀的长度。

展开：失配时 `j = next[j-1]`，主串指针不回退；匹配成功后可继续 `j = next[j-1]` 找重叠出现。

加分点：能说出「next 只依赖模式串，可预处理复用」。

**Q2：KMP 为什么是 O(n+m)？**

一句话结论：主串指针只前进，模式串指针的回退总次数受已匹配长度约束，整体线性。

展开：每次回退都减少 `j`，`j` 的增加来自主串前进，总增加 O(n)，总回退 O(n)。

加分点：能说出「朴素算法在重复前缀场景退化」。

**Q3：滚动哈希怎么处理碰撞？**

一句话结论：双哈希/随机 base 降低概率；哈希相等后再逐字符校验最稳。

展开：单哈希在对抗性输入下可被构造碰撞；模数要大，base 随机。

加分点：能说出「哈希适合预筛，最终相等要校验」。

**Q4：Trie 和 AC 自动机有什么区别？**

一句话结论：Trie 是单模式前缀结构；AC 自动机在 Trie 上加 fail 指针，支持多模式同时匹配。

展开：fail 指针指向最长后缀前缀；BFS 构建；匹配时沿 fail 跳转。

加分点：能说出「敏感词过滤用 AC，自动补全用 Trie」。

**Q5：Manacher 为什么能 O(n)？**

一句话结论：利用已知回文的对称性复用半径，每个位置最多扩展一次，总扩展 O(n)。

展开：统一奇偶回文；`p[mirror]` 给出可复用的半径；超出右边界再暴力扩展。

加分点：能说出「哨兵避免边界判断」。

## 小结

- **String 不可变**：循环拼接用 Builder；JDK 9+ 紧凑字符串按 coder 存 byte。
- **朴素匹配 O(nm)**，KMP 用前缀函数把主串指针不回退，做到 O(n+m)。
- **滚动哈希**用 O(1) 子串哈希，适合相等判断/去重；碰撞用双哈希 + 校验。
- **Trie 适合前缀，AC 自动机适合多模式匹配**；fail 指针 BFS 构建。
- **Manacher** 用对称性求最长回文 O(n)，但代码下标要小心。
- **正则不是万能**：嵌套量词可能指数回溯，大文本优先确定性算法。
