# 算法设计范式：贪心、分治、回溯与剪枝

> 定位：前面几篇讲的是「具体结构 + 具体题型」，这一篇讲「遇到陌生问题怎么想」。贪心、分治、回溯、剪枝、随机化是五套通用的解题范式；真正难的不是写出代码，而是判断「这道题能不能贪」「回溯会不会爆」「剪枝是否安全」。这一篇给判断标准、正确性证明方法和工程映射。

## 一、为什么需要「范式」

面试题千变万化，但解题思路的骨架有限：

| 范式 | 核心问题 | 典型信号 | 代价 |
|---|---|---|---|
| 贪心 | 每步选局部最优，最后是否全局最优？ | 区间调度、找零、 Huffman | 可能局部最优不是全局最优 |
| 分治 | 能否拆成独立子问题，再合并？ | 排序、二分、最近点对 | 递归/合并成本 |
| 回溯 | 能否枚举所有选择，并剪掉无效分支？ | 排列、组合、棋盘、路径 | 指数级 |
| 动态规划 | 子问题重叠且有最优子结构？ | 计数、最优值、序列 | 状态空间 |
| 随机化 | 用随机性换期望复杂度/简洁性？ | 快排、采样、哈希 | 结果不确定 |

判断顺序通常是：**先看能不能贪（最简单）→ 不能则看子问题是否重叠（DP）→ 不重叠则分治/回溯**。但这不是死规则，最终要看问题结构。

## 二、贪心：最难的是证明

### 2.1 贪心的两个条件

1. **贪心选择性质**：每一步的局部最优选择，能构成某个全局最优解；
2. **最优子结构**：选完当前最优后，剩余问题的最优解 + 当前选择 = 全局最优。

只满足「看起来合理」不够。反例很多：

- 找零：面值 `[1, 3, 4]`，凑 6 元，贪心选 4 + 1 + 1（3 枚），最优是 3 + 3（2 枚）；
- 0-1 背包：按单位价值贪心，可能选错组合；
- 任务调度：按最早截止时间贪心对「单机、每个任务 1 单位时间」有效，加了权重就不一定。

### 2.2 贪心正确性怎么证

最常用的是**交换论证（exchange argument）**：

1. 假设存在一个最优解 `OPT`，它第一步没有选贪心选的 `g`；
2. 把 `OPT` 中的某个元素替换成 `g`，证明结果不会变差；
3. 反复替换，得到一个包含贪心选择的最优解；
4. 对剩余子问题归纳。

以「区间调度：选最多不重叠区间」为例：

- 贪心策略：每次选**结束时间最早**的区间；
- 证明：设最优解第一个区间是 `o`，贪心选的是 `g`（结束更早）。把 `o` 换成 `g`，`g` 的结束时间更早，不会与后续区间冲突，所以替换后仍是最优；归纳即可。

注意：选「开始最早」或「持续时间最短」都不对，反例很容易构造。

### 2.3 经典贪心模型

| 问题 | 贪心策略 | 证明要点 |
|---|---|---|
| 区间调度 | 结束时间最早 | 交换论证 |
| 区间覆盖 | 每次选能覆盖当前起点、且右端最远的 | 覆盖范围最大化 |
| Huffman 编码 | 每次合并权值最小的两棵树 | 最优前缀码 |
| 最小生成树 | Kruskal 选最小边 / Prim 选最近点 | 割性质 |
| 任务调度（单机、单位时间） | 截止时间最早 | 交换论证 |
| 分糖果/加油站 | 局部剩余量/最远可达 | 维护可行区间 |

### 2.4 贪心的工程映射

- **限流/排队**：优先处理截止时间早的请求，避免大面积超时；
- **缓存淘汰**：LRU 是「最近最少使用」的贪心近似，不保证全局最优，但实现简单；
- **任务编排**：DAG 拓扑 + 最早截止时间优先，缩短平均完成时间；
- **资源分配**：按单位收益排序，适合可分割资源；不可分割时要小心。

## 三、分治：拆开、解决、合并

### 3.1 三步模板

```java
Result solve(Problem p) {
    if (p.isBaseCase()) return p.directSolve();
    List<Problem> subs = p.split();
    List<Result> results = new ArrayList<>();
    for (Problem sub : subs) results.add(solve(sub));
    return merge(results);
}
```

分治有效的条件：

1. 子问题相互独立（不重叠）；
2. 子问题规模显著减小；
3. 合并成本可控。

如果子问题重叠，分治会重复计算，应该用 DP 或记忆化。

### 3.2 复杂度：主定理

对 `T(n) = aT(n/b) + f(n)`：

| 情况 | 条件 | 结果 |
|---|---|---|
| 叶子主导 | `f(n) = O(n^(log_b a - ε))` | `T(n) = Θ(n^(log_b a))` |
| 均匀 | `f(n) = Θ(n^(log_b a))` | `T(n) = Θ(n^(log_b a) log n)` |
| 合并主导 | `f(n) = Ω(n^(log_b a + ε))` 且正则 | `T(n) = Θ(f(n))` |

例子：

- 归并排序：`a=2, b=2, f(n)=O(n)` → `Θ(n log n)`；
- 二分查找：`a=1, b=2, f(n)=O(1)` → `Θ(log n)`；
- 快速幂：`a=1, b=2, f(n)=O(1)` → `Θ(log n)`；
- Strassen 矩阵乘：`a=7, b=2` → `Θ(n^2.81)`。

面试不需要背表，能写出递推式并判断「每层总成本」即可。

### 3.3 分治的工程映射

- **MapReduce/Spark**：shuffle 就是分治的「合并」阶段；
- **归并排序/外部排序**：大数据排序的基础；
- **二分查找/答案二分**：把搜索空间减半；
- **CDN/分片**：按地理/哈希拆分请求，再聚合结果。

### 3.4 分治的坑

- 递归深度导致栈溢出；
- 子问题不独立，重复计算；
- 合并成本超过拆分收益；
- 切分不均匀，退化成 O(n²)。

## 四、回溯：枚举所有可能，但别真的枚举

### 4.1 状态树

回溯的本质是 DFS 一棵「选择树」：

- 路径：已经做出的选择；
- 选择列表：当前还能做什么；
- 结束条件：到达叶子/满足条件；
- 撤销：返回上一层前恢复状态。

```java
void backtrack(State s, List<Choice> choices, List<Result> res) {
    if (s.isComplete()) {
        res.add(s.snapshot());
        return;
    }
    for (Choice c : choices) {
        if (!s.canChoose(c)) continue; // 剪枝
        s.choose(c);
        backtrack(s, s.nextChoices(c), res);
        s.undo(c); // 恢复现场
    }
}
```

### 4.2 排列、组合、子集

| 题型 | 关键 | 去重 |
|---|---|---|
| 全排列 | 每个位置选一个未用元素 | 排序后跳过同层重复 |
| 组合 | 只能选后面的元素，避免顺序重复 | 排序后跳过同层重复 |
| 子集 | 每个元素选/不选 | 排序后跳过同层重复 |
| N 皇后 | 逐行放置，列/对角线冲突 | 位运算加速 |
| 数独 | 逐格填数，行/列/宫约束 | 候选数最少优先 |

### 4.3 剪枝：把指数级打下来

剪枝必须**安全**：不能剪掉可能存在解的分支。常见类型：

1. **可行性剪枝**：当前状态已经违反约束（如皇后冲突、和超过目标）；
2. **最优性剪枝**：当前成本已经大于已知最优解；
3. **搜索顺序剪枝**：先选约束最强的分支，尽早失败；
4. **记忆化**：相同状态只算一次（本质是 DP）；
5. **对称性剪枝**：旋转/翻转等对称解只保留一个。

例：组合求和，若数组已排序，当前和超过 target 就可以 break，因为后面的数更大。

### 4.4 回溯的复杂度

- 子集：O(2ⁿ)；
- 排列：O(n!)；
- N 皇后：O(n!) 级别，但剪枝后实际远小；
- 组合：O(C(n,k))。

面试时要说清「最坏复杂度」和「剪枝后的实际规模」，不要假装回溯是多项式。

### 4.5 回溯的工程映射

- 规则引擎/决策树；
- 路径规划（小规模）；
- 配置组合/测试用例生成；
- 拼图/排班/装箱。

工程上大规模问题不会用纯回溯，会用启发式/整数规划/约束求解器。

## 五、随机化：用概率换简单

### 5.1 随机化快排

固定 pivot 遇到有序数组会退化；随机选 pivot 后，期望复杂度 O(n log n)，最坏仍是 O(n²)，但概率极低。

### 5.2 水库采样

从长度未知的流中均匀采样 k 个：

```java
int[] reservoir = new int[k];
int i = 0;
for (int x : stream) {
    if (i < k) reservoir[i] = x;
    else {
        int j = ThreadLocalRandom.current().nextInt(i + 1);
        if (j < k) reservoir[j] = x;
    }
    i++;
}
```

每个元素被选中的概率都是 k/n。

### 5.3 哈希与去重

- 布隆过滤器用随机哈希换空间；
- MinHash 用随机排列估计 Jaccard 相似度；
- 一致性哈希用哈希环减少节点变动的影响。

随机化的代价是「结果不确定」，工程上要能接受假阳性/误差，或做多次验证。

## 六、范式怎么选

| 问题特征 | 首选 | 备选 |
|---|---|---|
| 每步有明确局部最优，且可证明 | 贪心 | DP |
| 子问题独立、可合并 | 分治 | 递归 |
| 要枚举所有解/计数 | 回溯 + 剪枝 | DP |
| 子问题重叠、求最优/计数 | DP | 记忆化搜索 |
| 数据量大、允许近似 | 随机化/采样 | 分治 |
| 约束复杂、规模小 | 回溯/约束求解 | DP |

一个实用判断：**先问「子问题是否重叠」**。重叠 → DP；不重叠 → 分治；需要枚举所有解 → 回溯；每步有可证明的局部最优 → 贪心。

## 七、工程映射：算法范式不是只用于面试

- **限流**：令牌桶是贪心式补充，漏桶是队列平滑；
- **负载均衡**：一致性哈希是随机化 + 取模的折中；
- **任务调度**：DAG 拓扑 + 贪心优先级；
- **数据分片**：哈希分桶是分治；
- **配置搜索**：回溯 + 剪枝用于小规模组合；
- **容量规划**：分治/二分答案用于求最小资源。

## 八、分支限界：带「上界」的回溯

回溯是深度优先，分支限界（Branch and Bound）通常用优先队列做「最佳优先搜索」，并用上界/下界剪枝。

以 0-1 背包为例：

- 节点表示「前 i 个物品、当前价值、当前重量」；
- 上界 = 当前价值 + 剩余物品按单位价值装满背包的收益；
- 若上界 ≤ 已知最优解，剪掉该分支；
- 优先扩展上界最大的节点。

```text
UpperBound(node) = value + (cap - weight) * bestUnitValue
if UpperBound(node) <= best: prune
```

分支限界适合组合优化（背包、TSP、调度），但最坏仍是指数级；它的价值在于「平均情况下大幅剪枝」。

## 九、启发式搜索：A* 与可采纳性

### 9.1 A* 的评估函数

```text
f(n) = g(n) + h(n)
```

- `g(n)`：从起点到 n 的实际代价；
- `h(n)`：从 n 到终点的估计代价；
- `f(n)`：经过 n 的估计总代价。

A* 每次扩展 `f` 最小的节点。

### 9.2 可采纳与一致性

- **可采纳（admissible）**：`h(n)` 永远不高估真实代价，保证最优解；
- **一致（consistent）**：`h(n) ≤ cost(n, n') + h(n')`，保证每个节点只扩展一次。

例：网格最短路用曼哈顿距离；若允许斜走，用切比雪夫/八向距离。启发函数高估会失去最优性，低估则退化成 Dijkstra。

### 9.3 A* 的工程映射

- 地图导航（路网 + 直线距离启发）；
- 游戏寻路；
- 拼图/规划；
- 资源调度中的启发式搜索。

## 十、模拟退火与遗传算法：什么时候值得用

这两类属于「元启发式」，不保证最优，适合解空间巨大、没有精确多项式算法的场景。

- **模拟退火**：从高温随机搜索，逐步降温，允许接受较差解以跳出局部最优；
- **遗传算法**：编码、选择、交叉、变异，迭代种群。

工程上真正用它们的场景不多（排班、装箱、参数搜索），面试只需知道：

1. 不保证最优；
2. 参数敏感、调参成本高；
3. 能用精确算法/启发式规则时优先用简单方法。

## 十一、范式组合：一道题可能用三种思想

以「带时间窗的配送路径」为例：

1. **图建模**：把订单/仓库建成点，距离是边权；
2. **贪心构造初始解**：按截止时间/距离选下一个点；
3. **回溯/分支限界**：对小规模订单做邻域搜索；
4. **DP**：对固定顺序的装车问题做状态压缩；
5. **随机化**：多次构造取较优解。

真实问题很少只用一种范式。面试时如果卡住，可以问自己：

- 能不能先构造一个可行解（贪心）？
- 能不能把问题拆小（分治）？
- 能不能枚举并剪枝（回溯）？
- 子问题是否重叠（DP）？
- 能不能接受近似（随机化）？

## 十二、算法设计检查清单

写完一个方案，按顺序自查：

1. **约束**：数据量、内存、时间、精度，是否都满足？
2. **正确性**：边界、重复、空集、极值是否覆盖？
3. **复杂度**：时间/空间都说得出，最坏情况是什么？
4. **证明**：贪心有交换论证，DP 有状态/转移，分治有递推式。
5. **可实现**：代码是否能在面试 30 分钟内写完？
6. **可测试**：能否用小数据对拍暴力解？
7. **可退化**：数据规模变小时，方案是否仍然正确？
8. **可解释**：能否用三句话向面试官说清思路？

## 面试高频问法

**Q1：怎么证明一个贪心策略是对的？**

一句话结论：用交换论证：假设最优解第一步不选贪心选择，把它替换成贪心选择，证明不变差，再归纳。

展开：先证贪心选择性质，再证最优子结构；举反例时只要一个就够。

加分点：能说出「找零、0-1 背包为什么贪心失效」。

**Q2：分治和 DP 的区别是什么？**

一句话结论：分治的子问题独立、不重叠；DP 的子问题重叠，需要保存结果避免重复计算。

展开：归并排序是分治；斐波那契递归是重叠，改成 DP/记忆化。

加分点：能说出「分治的合并成本决定总复杂度」。

**Q3：回溯什么时候会爆，怎么优化？**

一句话结论：解空间指数级时会爆；用可行性/最优性剪枝、搜索顺序、记忆化、对称性剪枝。

展开：先估解空间大小，再决定是否用回溯；大规模问题换启发式/整数规划。

加分点：能说出「剪枝必须安全，不能剪掉可行解」。

**Q4：随机化快排的最坏复杂度还是 O(n²)，为什么可用？**

一句话结论：随机 pivot 让最坏情况依赖随机数，期望 O(n log n)，实际几乎不出现；工程上还可加三路 partition。

展开：最坏是每次选到极值；随机化后概率极低。

加分点：能说出「随机化不消除最坏，只降低概率」。

**Q5：怎么判断一道陌生题该用什么范式？**

一句话结论：先看子问题是否重叠，再看是否每步有可证明的局部最优，最后看是否要枚举所有解。

展开：重叠→DP；独立→分治；局部最优可证→贪心；枚举→回溯；数据量大且可近似→随机化。

加分点：能结合题目约束（n 的范围、是否要求精确）判断。

## 小结

- **贪心难在证明**：交换论证是标准工具；找零、背包等反例说明「局部最优不等于全局最优」。
- **分治看子问题独立性与合并成本**；主定理用于快速判断复杂度。
- **回溯是带剪枝的 DFS**：路径、选择、结束条件、撤销四件事；剪枝必须安全。
- **随机化用概率换简单**：期望复杂度好，但最坏仍可能差。
- **范式选择先看子问题是否重叠**，再结合规模、精度、约束。
