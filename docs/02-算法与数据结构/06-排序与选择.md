# 排序与选择：理解 partition 比背代码重要

> 定位：排序是算法的「基本功考试」：面试让你手写快排，工程却几乎从不让你手写。这一篇讲清比较排序的边界、partition 的两种写法、稳定性与 Java 的排序实现，最后落到「TopK/第 k 大」的选择算法——这才是工程里真正会用的部分。

## 一、先看全貌：没有万能排序

| 算法 | 平均 | 最坏 | 空间 | 稳定 | 适用 |
|---|---|---|---|---|---|
| 冒泡 | O(n²) | O(n²) | O(1) | 是 | 教学，不用于生产 |
| 插入 | O(n²) | O(n²) | O(1) | 是 | 小数组/近乎有序 |
| 选择 | O(n²) | O(n²) | O(1) | 否 | 交换次数少 |
| 快排 | O(n log n) | O(n²) | O(log n) | 否 | 通用内存排序 |
| 归并 | O(n log n) | O(n log n) | O(n) | 是 | 链表、外部排序、稳定需求 |
| 堆排 | O(n log n) | O(n log n) | O(1) | 否 | 空间受限 |
| 计数 | O(n+k) | O(n+k) | O(k) | 是 | 小范围整数 |
| 基数 | O(d(n+k)) | O(d(n+k)) | O(n+k) | 是 | 定长整数/字符串 |
| TimSort | O(n log n) | O(n log n) | O(n) | 是 | Java 对象数组默认 |

「稳定」指相等元素的相对顺序不变。对对象排序时，稳定性常常比常数更重要：先按年龄排、再按姓名排，稳定排序能保留第二次的次序。

## 二、快排：partition 是核心

### 2.1 Lomuto 分区（好写好懂）

```java
int partition(int[] a, int l, int r) {
    int pivot = a[r];
    int i = l;
    for (int j = l; j < r; j++) {
        if (a[j] < pivot) {
            swap(a, i, j);
            i++;
        }
    }
    swap(a, i, r);
    return i;
}
```

`[l, i)` 是小于 pivot 的区域，`[i, j)` 是大于等于 pivot 的区域，最后把 pivot 放到 `i`。

### 2.2 Hoare 分区（交换次数少）

```java
int partitionHoare(int[] a, int l, int r) {
    int pivot = a[l + (r - l) / 2];
    int i = l - 1, j = r + 1;
    while (true) {
        do { i++; } while (a[i] < pivot);
        do { j--; } while (a[j] > pivot);
        if (i >= j) return j;
        swap(a, i, j);
    }
}
```

Hoare 返回的是分界点 `j`，递归用 `[l, j]` 和 `[j+1, r]`；不要误用 Lomuto 的 `[l, p-1]` / `[p+1, r]`，否则会死循环。

### 2.3 快排的四个优化

1. **随机/三数取中选 pivot**：避免有序数组退化成 O(n²)；
2. **三路 partition**：大量重复元素时分成 `< = >` 三段，避免重复元素反复划分；
3. **小数组切插入排序**：n < 16 时插入排序常数更小；
4. **尾递归优化**：先递归较小的一段，较大的一段循环处理，栈深 O(log n)。

### 2.4 快排最坏为什么是 O(n²)

每次 pivot 都是当前最小/最大，划分成 1 和 n-1，递归 n 层，每层 O(n)。有序数组 + 固定选最后一个元素，正好触发。

## 三、归并排序：稳定与链表友好

```java
void mergeSort(int[] a, int l, int r, int[] tmp) {
    if (l >= r) return;
    int m = l + (r - l) / 2;
    mergeSort(a, l, m, tmp);
    mergeSort(a, m + 1, r, tmp);
    int i = l, j = m + 1, k = l;
    while (i <= m && j <= r) tmp[k++] = a[i] <= a[j] ? a[i++] : a[j++];
    while (i <= m) tmp[k++] = a[i++];
    while (j <= r) tmp[k++] = a[j++];
    System.arraycopy(tmp, l, a, l, r - l + 1);
}
```

归并的优点是稳定、最坏也是 O(n log n)；缺点是 O(n) 额外空间。链表归并不需要额外数组，只要改指针，所以「链表排序」优先归并。

## 四、堆排序：原地但不稳定

```java
void heapSort(int[] a) {
    int n = a.length;
    for (int i = n / 2 - 1; i >= 0; i--) siftDown(a, i, n);
    for (int end = n - 1; end > 0; end--) {
        swap(a, 0, end);
        siftDown(a, 0, end);
    }
}
```

建堆 O(n)，每次取堆顶放到末尾，再对剩余部分下沉，总 O(n log n)，空间 O(1)。缺点是不稳定、常数较大、缓存不友好。

## 五、Java 的排序实现

### 5.1 基本类型用双轴快排

`Arrays.sort(int[])` 使用 Dual-Pivot Quicksort，不稳定；基本类型没有「相等对象」的概念，稳定性无意义。

### 5.2 对象数组用 TimSort

`Arrays.sort(Object[])` / `Collections.sort` 使用 TimSort，稳定，O(n log n)。TimSort 利用输入中的有序片段（run），对部分有序数据接近 O(n)。

### 5.3 工程建议

- 别手写排序，用 `Arrays.sort` / `Collections.sort`；
- 需要稳定且对象排序：TimSort 默认就是；
- 需要按多个字段排序：`Comparator.thenComparing`；
- 大对象排序注意比较器开销，避免在比较器里做 IO/复杂计算；
- 并行排序 `Arrays.parallelSort` 适合大数组，但小数组和单核环境反而更慢。

## 六、选择问题：第 k 大/前 k 个

### 6.1 快速选择（Quickselect）

```java
int findKth(int[] a, int k) { // 第 k 小，k 从 1 开始
    int l = 0, r = a.length - 1, target = k - 1;
    while (l <= r) {
        int p = partition(a, l, r);
        if (p == target) return a[p];
        if (p < target) l = p + 1;
        else r = p - 1;
    }
    return -1;
}
```

平均 O(n)，最坏 O(n²)（同快排）；随机化 pivot 可把最坏概率降到极低。

### 6.2 堆选择

- 第 k 大：小顶堆，堆里留最大的 k 个，堆顶是第 k 大；
- 第 k 小：大顶堆，堆里留最小的 k 个，堆顶是第 k 小；
- 复杂度 O(n log k)，适合数据流/超大数组。

### 6.3 什么时候用哪个

| 场景 | 方案 | 原因 |
|---|---|---|
| 静态数组，只要第 k 个 | Quickselect | 平均 O(n)，原地 |
| 数据流/持续追加 | 堆 | 维护 k 个元素，O(log k) 更新 |
| 要前 k 个且有序 | 堆 + 排序 | O(n log k + k log k) |
| k 接近 n | 直接排序 | O(n log n)，代码简单 |
| 内存放不下 | 分块 TopK + 归并 | 见海量数据篇 |

## 七、排序的工程坑

- **比较器不满足全序**：`a < b` 和 `b < a` 同时为真，TimSort 会抛 `IllegalArgumentException: Comparison method violates its general contract`；
- **比较器里做减法溢出**：`(a, b) -> a - b` 在极端值下溢出，用 `Integer.compare`；
- **可变对象排序**：排序过程中修改被比较字段，结果不可预测；
- **稳定性误判**：基本类型排序不稳定，对象排序才稳定；
- **并行排序滥用**：小数组并行开销大于收益。

## 八、非比较排序：计数、基数、桶

比较排序的下界是 Ω(n log n)；如果数据有额外结构（小范围整数、定长字符串），可以突破。

### 8.1 计数排序

适合值域 `[min, max]` 不大的整数：

```java
void countingSort(int[] a) {
    int min = Arrays.stream(a).min().getAsInt();
    int max = Arrays.stream(a).max().getAsInt();
    int[] cnt = new int[max - min + 1];
    for (int x : a) cnt[x - min]++;
    int k = 0;
    for (int i = 0; i < cnt.length; i++) {
        while (cnt[i]-- > 0) a[k++] = i + min;
    }
}
```

时间 O(n + k)，空间 O(k)。k 远大于 n 时浪费内存；只适合整数/可映射为整数。

### 8.2 基数排序

按位从低到高，每一位用计数排序，要求「稳定」：

```java
void radixSort(int[] a) {
    int max = Arrays.stream(a).max().getAsInt();
    for (int exp = 1; max / exp > 0; exp *= 10) {
        countingSortByDigit(a, exp);
    }
}
```

复杂度 O(d(n + base))，d 是位数。适合定长整数/字符串；负数和浮点要特殊处理。

### 8.3 桶排序

把数据分到若干个桶，桶内再排序，最后合并。适合均匀分布；分布不均会退化。

### 8.4 非比较排序的边界

- 计数排序值域不能太大；
- 基数排序依赖稳定子排序；
- 桶排序依赖分布假设；
- 对象排序不能直接用（要映射 key）。

## 九、稳定性的证明与工程意义

### 9.1 为什么归并稳定

合并两个有序段时，相等元素优先取左边；左边在原数组中本来就在右边之前，所以相对顺序不变。

### 9.2 为什么快排不稳定

partition 的 `swap` 会把远处元素换到前面，相等元素的相对位置可能被破坏。

### 9.3 稳定性为什么重要

多字段排序：

```java
list.sort(comparing(User::getAge));
list.sort(comparing(User::getName));
```

如果第二次排序稳定，年龄相同的用户会保持第一次的年龄顺序；不稳定则可能乱。

### 9.4 Java 的排序契约

- `Arrays.sort(int[])` 不稳定；
- `Arrays.sort(Object[])` / `List.sort` 稳定（TimSort）；
- `Comparator` 必须满足全序：自反、反对称、传递；
- 比较器返回 `Integer.MIN_VALUE` 做减法会溢出，用 `Integer.compare`。

## 十、排序选型决策树

```text
数据量小（n < 16）？
  → 插入排序（常数小）

数据是基本类型？
  → Arrays.sort（双轴快排，不稳定）

需要稳定 / 对象排序？
  → TimSort（Arrays.sort(Object[])）

内存受限？
  → 堆排序（O(1) 空间）

数据是定长整数/小值域？
  → 计数/基数排序

数据在磁盘 / 放不下？
  → 外部排序（分块 + 多路归并）

只要第 k 个 / 前 k 个？
  → Quickselect / 堆
```

工程上还有一层：**能上数据库/Spark 就不要手写排序**。排序的瓶颈通常在 IO、比较器开销和数据倾斜，不在算法本身。

## 十一、排序的测试与验证

排序代码最容易在边界出错，写完至少验证：

| 用例 | 检查 |
|---|---|
| 空数组/单元素 | 不越界 |
| 全相同 | 稳定性/分区正确 |
| 已有序 | 快排是否退化 |
| 逆序 | 归并/快排边界 |
| 含重复 | 三路分区/稳定 |
| 极值 | 比较器溢出 |
| 大数组 | 递归深度/栈 |

随机化测试：生成随机数组，与 `Arrays.sort` 的结果逐元素比较；重复 1000 次，比手工构造用例更有效。

## 十二、外部排序：数据放不下内存

### 12.1 为什么不能直接排序

100GB 数据、2GB 内存，无法一次加载。外部排序把数据分块：

1. 每次读一块（如 1GB）进内存，排序后写成有序小文件；
2. 对多个有序小文件做多路归并；
3. 边归并边写最终结果。

### 12.2 多路归并的细节

- 每个输入文件一个读缓冲区，输出一个写缓冲区；
- 归并路数 k 受内存与文件句柄限制；
- k 越大，比较次数越多，但 IO 次数越少；
- 用「败者树」可以把每次取最小的比较次数从 O(k) 降到 O(log k)。

### 12.3 外部排序的瓶颈

- 磁盘顺序读写带宽；
- 随机 IO（小文件太多时）；
- 归并阶段的临时空间；
- 数据倾斜（某个块特别大）。

工程上优先用数据库/Spark 的排序，不要手写；面试考的是「分块 + 归并」的思路。

## 十三、并行排序：不是线程越多越快

### 13.1 并行归并

把数组分成 P 段，分别排序，再两两归并。理论加速比受 Amdahl 定律限制：分段/合并的串行部分决定上限。

### 13.2 Java 的 parallelSort

`Arrays.parallelSort` 使用 Fork/Join，把数组切成小块并行排序，再合并。适合大数组、CPU 核多；小数组的线程开销大于收益。

### 13.3 并行排序的坑

- 比较器/交换操作必须是线程安全的；
- 数据倾斜导致某些线程更忙；
- 合并阶段可能成为瓶颈；
- 并发修改数组会导致未定义行为。

## 十四、TimSort：Java 对象排序的默认实现

TimSort 是「归并 + 插入」的混合：

1. 扫描数组，找自然有序的 run（升序或严格降序）；
2. 短 run 用插入排序扩展到最小长度；
3. 用归并合并 run，维护栈上的不变量；
4. 对部分有序数据，接近 O(n)。

关键点：

- **稳定**：合并时相等元素取左边；
- **自适应**：利用已有顺序；
- **最坏 O(n log n)**：不会退化；
- 比较器必须满足全序，否则抛 `IllegalArgumentException`。

## 十五、比较器设计：排序正确性的半边天

### 15.1 常见错误

```java
// 错误：减法溢出
(a, b) -> a - b

// 正确
(a, b) -> Integer.compare(a, b)

// 多字段
Comparator.comparing(User::getAge)
          .thenComparing(User::getName)
          .thenComparing(User::getId)
```

### 15.2 全序契约

比较器必须满足：

- 自反：`compare(a,a)==0`；
- 反对称：`compare(a,b)` 与 `compare(b,a)` 符号相反；
- 传递：`a<b, b<c` 则 `a<c`；
- 一致性：只要对象没变，结果不变。

违反契约的典型后果：TimSort 抛异常、排序结果错乱、二分查找失效。

### 15.3 空值与可变字段

- 用 `Comparator.nullsFirst/nullsLast` 处理 null；
- 排序过程中不要修改被比较字段；
- 比较器里不要做 IO/远程调用，否则排序会慢几个数量级。

## 面试高频问法

**Q1：快排最坏 O(n²)，为什么工程还用它？**

一句话结论：平均 O(n log n)、原地、常数小、缓存友好；随机化 pivot + 三路 partition 后，最坏情况几乎不出现。

展开：Java 基本类型用双轴快排；对象排序用 TimSort，因为需要稳定。

加分点：能说出「有序数组 + 固定 pivot 会退化，随机化可避免」。

**Q2：归并排序为什么稳定，快排为什么不稳定？**

一句话结论：归并合并时相等元素优先取左边，保持原序；快排的 swap 会跨距离交换，相等元素的相对顺序可能改变。

展开：稳定性取决于「相等时怎么处理」；归并 `a[i] <= a[j]` 取左，快排无法保证。

加分点：能说出「对象排序需要稳定，基本类型不需要」。

**Q3：第 k 大怎么求？**

一句话结论：静态数组用 Quickselect 平均 O(n)；数据流/超大数组用小顶堆 O(n log k)。

展开：小顶堆保留最大的 k 个，堆顶是第 k 大；求第 k 小用大顶堆。

加分点：能说出「k 很小时堆更省内存，k 接近 n 时直接排序」。

**Q4：Java 的 Arrays.sort 用了什么算法？**

一句话结论：基本类型用 Dual-Pivot Quicksort（不稳定），对象数组用 TimSort（稳定）。

展开：TimSort 利用有序 run，部分有序数据接近 O(n)；并行排序用 `parallelSort`。

加分点：能说出「比较器违反全序会抛 IllegalArgumentException」。

## 小结

- **没有万能排序**：快排通用、归并稳定、堆排省空间、计数/基数适合特定数据。
- **快排核心是 partition**：Lomuto 好写，Hoare 交换少；随机 pivot + 三路 + 小数组插入是工程优化。
- **归并稳定但费空间**，链表排序优先归并。
- **Java 基本类型用双轴快排，对象用 TimSort**；别手写生产排序。
- **选择问题**：静态第 k 用 Quickselect，数据流用堆；k 接近 n 直接排序。
