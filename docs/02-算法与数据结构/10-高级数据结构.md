# 高级数据结构：并查集、树状数组、线段树与跳表

> 定位：前面讲了数组、链表、哈希、堆、Trie，这些是「日常结构」；这一篇讲「面试进阶 + 工程专用」的四类结构：并查集、树状数组、线段树、跳表，外加磁盘索引的 B+ 树/LSM。重点不是背代码，而是知道它们各自解决什么问题、复杂度为什么成立、什么时候不该用。

## 一、并查集：动态连通性

### 1.1 解决什么问题

并查集（Disjoint Set Union, DSU）维护若干个不相交集合，支持：

- `find(x)`：x 属于哪个集合（返回代表元）；
- `union(a, b)`：合并两个集合；
- `connected(a, b)`：判断是否同集合。

典型场景：朋友圈、岛屿数量、冗余连接、Kruskal 最小生成树、账户合并、网络连通性。

### 1.2 基本实现

```java
class DSU {
    private final int[] parent;

    DSU(int n) {
        parent = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
    }

    int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]); // 路径压缩
        return parent[x];
    }

    void union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra != rb) parent[rb] = ra;
    }
}
```

没有优化时，树可能退化成链，`find` 变 O(n)。两个优化：

1. **路径压缩**：查找时把路径上的节点直接挂到根；
2. **按大小/秩合并**：把小树挂到大树，控制树高。

```java
class DSU {
    private final int[] parent, size;

    DSU(int n) {
        parent = new int[n];
        size = new int[n];
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }
    }

    int find(int x) {
        return parent[x] == x ? x : (parent[x] = find(parent[x]));
    }

    boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;
        if (size[ra] < size[rb]) { int t = ra; ra = rb; rb = t; }
        parent[rb] = ra;
        size[ra] += size[rb];
        return true;
    }
}
```

复杂度：路径压缩 + 按大小合并，均摊 O(α(n))，α 是反阿克曼函数，实际可视为常数。

### 1.3 带权并查集

有时要维护「节点到根的距离/权值」，例如「食物链」「带权关系」：

```java
int find(int x) {
    if (parent[x] == x) return x;
    int root = find(parent[x]);
    dist[x] += dist[parent[x]]; // 先递归，再累加
    return parent[x] = root;
}
```

关键是**先保存旧父节点，再递归压缩**，否则 `dist` 会算错。

### 1.4 种类并查集

当关系有多个类别（朋友/敌人、同类/异类），可以把每个对象拆成多个「虚拟节点」，用偏移量表示状态。例如 `x` 的朋友是 `x`，敌人是 `x+n`；合并时按关系映射。

### 1.5 并查集的边界

- 只支持合并，不支持删除/分裂；
- 路径压缩后无法保留原树结构；
- 需要持久化/可撤销时，用「按秩合并但不路径压缩」+ 回滚栈；
- 动态加点要预分配或使用 Map 版 DSU。

## 二、树状数组：前缀和 + 单点更新

### 2.1 解决什么问题

树状数组（Fenwick Tree / BIT）支持：

- 单点更新 O(log n)；
- 前缀和查询 O(log n)；
- 区间和 = 两个前缀和相减。

它比线段树代码短、常数小，适合「频繁单点更新 + 前缀查询」；不支持区间更新（除非用差分技巧）。

### 2.2 lowbit 的原理

```java
int lowbit(int x) { return x & -x; }
```

`lowbit(x)` 取出 x 的二进制最低位的 1。例如 6 = 110，lowbit = 2；8 = 1000，lowbit = 8。

树状数组的 `tree[i]` 维护区间 `(i - lowbit(i), i]` 的和。查询前缀和时，不断 `i -= lowbit(i)`；更新时，不断 `i += lowbit(i)`。

### 2.3 代码

```java
class Fenwick {
    private final int[] tree;
    private final int n;

    Fenwick(int n) {
        this.n = n;
        tree = new int[n + 1];
    }

    void add(int i, int delta) { // i 从 1 开始
        for (; i <= n; i += i & -i) tree[i] += delta;
    }

    int sum(int i) { // 前缀 [1..i]
        int s = 0;
        for (; i > 0; i -= i & -i) s += tree[i];
        return s;
    }

    int rangeSum(int l, int r) {
        return sum(r) - sum(l - 1);
    }
}
```

### 2.4 区间更新 + 单点查询

用差分数组建树状数组：

- 区间 `[l, r]` 加 v：`add(l, v)`、`add(r+1, -v)`；
- 单点查询 x：`sum(x)`。

### 2.5 区间更新 + 区间查询

需要维护两个树状数组：

```text
sum[1..x] = (x+1) * sum(B1, x) - sum(B2, x)
B1 存差分 d[i]，B2 存 d[i]*i
```

这是树状数组的进阶用法，面试少见，但工程里用于「区间加、区间求和」。

### 2.6 二维树状数组

`tree[i][j]` 按两个维度 lowbit 更新/查询，复杂度 O(log²n)。适合二维矩阵的单点更新 + 子矩阵前缀和。

### 2.7 树状数组的边界

- 下标从 1 开始，0 会死循环；
- 只适合满足结合律且可差分的运算（加法、异或）；最大值/最小值不适合；
- 区间更新需要差分，区间查询需要双 BIT；
- 数据范围大时先离散化。

## 三、线段树：区间操作的万能结构

### 3.1 解决什么问题

线段树支持：

- 区间查询（和/最值/GCD）；
- 区间更新（加/赋值）；
- 单点更新；
- 维护复杂标记（懒标记）。

复杂度 O(log n)，比树状数组灵活，但代码更长、常数更大。

### 3.2 结构

用数组存树，节点 `p` 表示区间 `[l, r]`，左子 `2p`，右子 `2p+1`。叶子是单点。

```java
class SegTree {
    int[] tree, lazy;
    int n;

    SegTree(int[] a) {
        n = a.length;
        tree = new int[4 * n];
        lazy = new int[4 * n];
        build(1, 0, n - 1, a);
    }

    void build(int p, int l, int r, int[] a) {
        if (l == r) { tree[p] = a[l]; return; }
        int m = (l + r) / 2;
        build(p * 2, l, m, a);
        build(p * 2 + 1, m + 1, r, a);
        tree[p] = tree[p * 2] + tree[p * 2 + 1];
    }

    void pushDown(int p, int l, int r) {
        if (lazy[p] == 0) return;
        int m = (l + r) / 2;
        tree[p * 2] += lazy[p] * (m - l + 1);
        tree[p * 2 + 1] += lazy[p] * (r - m);
        lazy[p * 2] += lazy[p];
        lazy[p * 2 + 1] += lazy[p];
        lazy[p] = 0;
    }

    void add(int p, int l, int r, int ql, int qr, int v) {
        if (ql <= l && r <= qr) {
            tree[p] += v * (r - l + 1);
            lazy[p] += v;
            return;
        }
        pushDown(p, l, r);
        int m = (l + r) / 2;
        if (ql <= m) add(p * 2, l, m, ql, qr, v);
        if (qr > m) add(p * 2 + 1, m + 1, r, ql, qr, v);
        tree[p] = tree[p * 2] + tree[p * 2 + 1];
    }

    int query(int p, int l, int r, int ql, int qr) {
        if (ql <= l && r <= qr) return tree[p];
        pushDown(p, l, r);
        int m = (l + r) / 2, ans = 0;
        if (ql <= m) ans += query(p * 2, l, m, ql, qr);
        if (qr > m) ans += query(p * 2 + 1, m + 1, r, ql, qr);
        return ans;
    }
}
```

### 3.3 懒标记的本质

区间更新时，不立刻更新所有叶子，而是在节点上打标记；查询/下次更新经过该节点时，再把标记下推。这样每次操作只访问 O(log n) 个节点。

懒标记要满足：

- 标记可叠加（加法、赋值要注意顺序）；
- 下推后当前节点标记清空；
- 子节点长度参与计算。

### 3.4 常见变体

| 变体 | 说明 |
|---|---|
| 区间加、区间和 | 最基础，懒标记存增量 |
| 区间赋值、区间最值 | 标记需要覆盖/清空逻辑 |
| 区间乘、区间加 | 两个标记，注意先乘后加 |
| 动态开点 | 值域大但实际节点少，按需创建 |
| 权值线段树 | 按值域建树，查第 k 小/排名 |
| 可持久化 | 保留历史版本，主席树 |
| 线段树合并 | 多棵树合并，统计信息 |
| Segment Tree Beats | 区间取 min/max 等复杂操作 |

### 3.5 线段树的工程映射

- 区间统计/监控聚合；
- 订单金额区间对账；
- 游戏排行榜/区间最值；
- 时间轴上的区间覆盖；
- 大规模数据的分段聚合。

### 3.6 线段树的坑

- 数组要开 4n，不是 2n；
- 递归深度 O(log n)，安全；
- 懒标记下推时机：查询/更新子节点前；
- 多标记顺序（先乘后加）写错会得到错误结果；
- 离散化后值域变小，别直接按下标建树。

## 四、跳表：链表的二分

### 4.1 解决什么问题

链表查找 O(n)，加「多级索引」后变成 O(log n) 期望。跳表就是「带索引的有序链表」，支持：

- 查找、插入、删除 O(log n) 期望；
- 范围查询；
- 天然有序，适合排行榜。

Redis 的有序集合（ZSet）就用跳表 + 哈希表实现。

### 4.2 结构

每个节点有多个层指针，层数随机：

```java
class Node {
    int val;
    Node[] next;
    Node(int val, int level) {
        this.val = val;
        this.next = new Node[level];
    }
}
```

查找从最高层开始，能往右就往右，不能就往下一层。

### 4.3 查找

```java
boolean search(int target) {
    Node cur = head;
    for (int i = level - 1; i >= 0; i--) {
        while (cur.next[i] != null && cur.next[i].val < target) {
            cur = cur.next[i];
        }
    }
    cur = cur.next[0];
    return cur != null && cur.val == target;
}
```

### 4.4 插入与删除

- 插入：先找到每层的前驱，随机生成层数，逐层插入；
- 删除：找到每层前驱，逐层改指针；
- 层数随机：每次 `random < 0.5` 升一层，期望层数 O(log n)。

### 4.5 复杂度与工程

- 期望 O(log n)，最坏 O(n)（随机性差）；
- 实现比红黑树简单，范围查询更自然；
- Redis ZSet：跳表 + 哈希表，哈希表存 member→score，跳表按 score 排序；
- 并发跳表可用 CAS 实现无锁/细粒度锁。

### 4.6 跳表 vs 红黑树

| 维度 | 跳表 | 红黑树 |
|---|---|---|
| 实现难度 | 简单 | 复杂（旋转/变色） |
| 范围查询 | 链表顺序，天然友好 | 中序遍历 |
| 最坏复杂度 | O(n)（概率低） | O(log n) |
| 并发 | 容易细粒度锁 | 难 |
| 内存 | 多级指针，较大 | 每节点固定 |

工程选型：需要简单、范围查询、并发友好 → 跳表；需要严格最坏 O(log n)、内存敏感 → 红黑树。

## 五、B 树、B+ 树与 LSM：磁盘结构

### 5.1 为什么磁盘不用二叉树

磁盘 IO 以页（4KB/16KB）为单位，一次 IO 很贵。二叉树每层只比较一个 key，树高 log₂n，IO 次数多；B 树一个节点存几百个 key，树高 3–4 层就能索引亿级数据。

### 5.2 B 树 vs B+ 树

| 维度 | B 树 | B+ 树 |
|---|---|---|
| 数据位置 | 所有节点都可能存数据 | 数据只在叶子 |
| 叶子链表 | 无 | 有，范围查询快 |
| 查询稳定性 | 可能在内部节点命中 | 每次都到叶子 |
| 扇出 | 较低 | 较高 |

MySQL InnoDB 用 B+ 树：聚簇索引叶子存整行，二级索引叶子存主键；范围查询沿叶子链表扫描。

### 5.3 LSM 树

LSM（Log-Structured Merge Tree）把随机写变成顺序写：

- 写入 WAL + MemTable；
- MemTable 满了刷成 SSTable；
- 后台合并（compaction）；
- 读时先查 MemTable，再查多层 SSTable，可能用布隆过滤器。

优点：写吞吐高；缺点：读放大、写放大、空间放大。RocksDB、HBase、Cassandra 都用 LSM。

### 5.4 选型

| 需求 | 结构 |
|---|---|
| 读多写少、范围查询 | B+ 树 |
| 写多读少、KV | LSM |
| 内存有序 | 红黑树/跳表 |
| 内存哈希 | 哈希表 |

## 六、高级结构选型表

| 需求 | 结构 | 复杂度 | 备注 |
|---|---|---|---|
| 动态连通性 | 并查集 | 近 O(1) | 只合并不分裂 |
| 单点更新 + 前缀和 | 树状数组 | O(log n) | 代码短、常数小 |
| 区间更新 + 区间查询 | 线段树 | O(log n) | 懒标记 |
| 第 k 小/排名 | 权值线段树/树状数组 | O(log n) | 需离散化 |
| 有序集合/排行榜 | 跳表 | O(log n) 期望 | Redis ZSet |
| 磁盘索引 | B+ 树 | O(log n) IO | 范围查询 |
| 写多读少 KV | LSM | 写 O(1) 摊还 | 读放大 |

## 七、线段树的进阶变体

### 7.1 动态开点

值域很大（如 10⁹）但实际操作少时，不建满 4n，而是按需创建节点：

```java
class Node {
    int sum, lazy;
    Node left, right;
}
```

每次更新/查询只创建经过的节点，空间 O(操作数 × log V)。适合「值域大、稀疏访问」。

### 7.2 权值线段树

按「值」建树，叶子表示某个值出现次数，内部节点表示区间计数。可以查：

- 第 k 小/第 k 大；
- 某个值的排名；
- 区间内有多少个数。

常与离散化配合：先把所有可能的值收集起来排序，用下标建树。

### 7.3 可持久化线段树（主席树）

每次更新只复制一条链，保留历史版本。适合：

- 区间第 k 小；
- 历史版本查询；
- 可持久化数组。

空间 O((n + 操作数) log n)，实现难度较高，面试出现频率低于「第 k 小 + 权值线段树」。

### 7.4 树套树

外层线段树/树状数组，内层平衡树/线段树，支持「区间第 k 小」「带修改的区间查询」。空间和时间都在 O(log²n) 级别，代码复杂，工程上更常用数据库/搜索引擎。

### 7.5 什么时候不该用

- 能用树状数组解决，就别上线段树；
- 能用离线排序/莫队解决，就别上树套树；
- 数据量小，暴力更快；
- 维护成本大于收益时，用现成数据库/搜索引擎。

## 面试高频问法

**Q1：并查集为什么接近 O(1)？**

一句话结论：路径压缩把树压扁，按大小合并控制树高，均摊复杂度是反阿克曼函数，实际可视为常数。

展开：`find` 递归压缩路径；`union` 按大小/秩合并；不优化时可能退化成链。

加分点：能说出「只支持合并，不支持删除/分裂」。

**Q2：树状数组和线段树怎么选？**

一句话结论：单点更新 + 前缀和/区间和用树状数组，代码短、常数小；区间更新、区间最值、复杂标记用线段树。

展开：树状数组不支持任意区间更新（要差分），也不适合最大值；线段树灵活但代码长。

加分点：能说出「树状数组 lowbit 的原理」。

**Q3：线段树的懒标记为什么能降复杂度？**

一句话结论：区间更新时只在覆盖节点打标记，不递归到叶子；查询/下次更新经过时再下推，每次只访问 O(log n) 个节点。

展开：标记要可叠加，下推后清空；多标记要注意顺序。

加分点：能说出「数组开 4n，查询前 pushDown」。

**Q4：跳表为什么能 O(log n)？**

一句话结论：多级索引让查找每次跳过一段，期望层数 O(log n)，每层平均走常数步。

展开：层数随机生成，`random < 0.5` 升层；最坏 O(n) 但概率极低。

加分点：能说出「Redis ZSet 用跳表 + 哈希表」。

**Q5：B+ 树和 LSM 怎么选？**

一句话结论：读多写少、范围查询用 B+ 树；写多读少、KV 高吞吐用 LSM。

展开：B+ 树读放大低、写放大高；LSM 顺序写快，但读要查多层，通常配布隆过滤器。

加分点：能说出「LSM 的 compaction 会带来写放大」。

**Q6：为什么 MySQL 用 B+ 树而不是跳表？**

一句话结论：磁盘 IO 按页算，B+ 树扇出大、树高低，3–4 次 IO 能索引亿级数据；跳表每层一个节点，IO 次数多。

展开：B+ 树叶子链表适合范围查询；跳表更适合内存有序结构。

加分点：能说出「B+ 树非叶子只存索引，数据在叶子」。

## 小结

- **并查集**解决动态连通性，路径压缩 + 按大小合并，近 O(1)。
- **树状数组**适合单点更新 + 前缀和，lowbit 是核心；区间更新要差分。
- **线段树**适合区间更新/查询，懒标记是降复杂度的关键。
- **跳表**用随机多级索引实现有序链表二分，Redis ZSet 的选择。
- **B+ 树适合磁盘读多写少，LSM 适合写多读少**；选型看读写比例与放大。
- 高级结构不是越复杂越好：**能用哈希/堆解决就别上树**。
