# 版本基线与更新说明

> 定位：技术文章最大的敌人不是写错，而是「过时」——三年前正确的默认值、源码行号、API 签名，今天可能已经变了。这一页声明整套知识库的版本基线、源码引用规范、更新与勘误机制，让读者知道「这篇是按哪个版本讲的」，也让贡献者知道该对齐什么。

## 一、为什么要声明版本基线

同一个问题，不同版本答案可能相反：

- HashMap 在 JDK 7 是头插法（并发扩容可能死循环），JDK 8 改成尾插 + 红黑树；
- MySQL 8.0.29 之前，`INSTANT` DDL 只支持在表末尾加列；之后才支持任意位置加列与删列；
- Spring Boot 2 用 `javax.*`，Spring Boot 3 全部迁到 `jakarta.*`；
- Redis 6 之前单线程模型，6.0 引入 IO 多线程，但命令执行仍是单线程；
- Kafka 3.x 逐步移除 ZooKeeper 依赖，KRaft 成为默认方向。

如果不声明基线，读者会拿着 JDK 8 的经验去排查 JDK 21 的问题，或者反过来。所以本库统一约定：**文章正文默认按下面的基线讲解；涉及版本差异时，必须在文中标注版本。**

## 二、统一版本基线

| 领域 | 基线版本 | 说明 |
|---|---|---|
| JDK | **JDK 21 LTS**（必要时提到 JDK 25 LTS） | 新特性文章覆盖 8-21；虚拟线程、Record、Sealed 以 21 为准 |
| Spring | **Spring Boot 3.x / Spring Framework 6.x** | 新文章会讲 Boot 4 / Framework 7 的方向，但细节标注「以 Release Notes 为准」 |
| 持久层 | MyBatis 3.5.x、Hibernate 6.x | JPA 文章按 Jakarta Persistence 3.1 讲 |
| MySQL | **MySQL 8.0** | 默认隔离级别 RR、`utf8mb4`、窗口函数、`INSTANT` DDL 均按 8.0 |
| PostgreSQL | PostgreSQL 16 | MVCC、VACUUM、逻辑复制、分区表按 16 讲 |
| Redis | Redis 7.x | 集群、持久化、`GEOSEARCH`、Function 等按 7.x |
| 消息队列 | Kafka 3.x、RocketMQ 5.x、RabbitMQ 3.13/4.x | Quorum Queue 与经典镜像队列的差异会单独标注 |
| 搜索引擎 | Elasticsearch 8.x | 向量检索、Java API Client 按 8.x |
| 容器 | **Kubernetes 1.30** | CNI、Gateway API、HPA、Operator 按 1.30 |
| 可观测性 | OpenTelemetry 1.x、Prometheus 2.x、Grafana 10+ | 语义约定（semconv）随版本变化，文中会注明 |
| 大数据 | Hadoop 3.x、Spark 3.5、Flink 1.19、Hive 3.x | Iceberg 1.5、Hudi 0.14+、Paimon 0.7+；Doris 2.x、StarRocks 3.x、ClickHouse 24.x |
| AI | Spring AI 1.x、LangChain4j 0.3x | 模型 API 与向量库 SDK 迭代快，以官方文档为准 |

> 基线不是「唯一正确版本」。如果你的生产环境是 JDK 17 + Boot 2.7，读文章时要主动做版本映射，尤其是 `javax/jakarta`、默认 GC、默认隔离级别、K8s API 版本这些差异点。

## 三、源码引用规范

本库强调「源码级实证」，但源码会随版本演进。引用时遵循：

1. **优先给类名 + 方法名**，例如 `HashMap.putVal`、`DispatcherServlet.doDispatch`，而不是只给行号。
2. 必须给行号时，说明是哪个版本、哪个仓库；行号只作定位参考，不作为唯一依据。
3. 不给「某行代码一定在 1234 行」这类易失效断言；需要时写成「在 `resize()` 中可以看到……」。
4. 参数默认值、阈值、常量，标注版本；无法确认时写「以实际版本为准」，不硬编。
5. 外部链接优先官方文档、JEP、RFC；不引用二手博客作为唯一依据。

## 四、内容更新策略

- **每半年**对照各组件 LTS/大版本，检查一次基线与「过时结论」。
- 大版本升级（如 JDK 21→25、Boot 3→4、K8s 1.30→1.33）时，优先更新：语言新特性、Spring 启动/自动配置、K8s 网络与 API、消息队列默认行为。
- 默认值、阈值、性能数字属于「高漂移内容」，更新时优先核对。
- 方法论、架构模式、系统设计类内容漂移慢，但仍需补充新案例与新约束（如 AI 成本、合规要求）。
- 新增文章必须写「参考资料」，并注明版本。
