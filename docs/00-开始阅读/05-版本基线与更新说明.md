# 版本基线与更新说明

> 定位：技术文章最大的敌人不是写错，而是「过时」——三年前正确的默认值、源码行号、API 签名，今天可能已经变了。这一页声明整套知识库的版本基线、源码引用规范、更新与勘误机制，让读者知道「这篇是按哪个版本讲的」，也让贡献者知道该对齐什么。

## 一、为什么要声明版本基线

同一个问题，不同版本答案可能相反：

- HashMap 在 JDK 7 是头插法（并发扩容可能死循环），JDK 8 改成尾插 + 红黑树；
- MySQL 8.0.29 之前，`INSTANT` DDL 只支持在表末尾加列；之后才支持任意位置加列与删列；
- Spring Boot 2 用 `javax.*`，Spring Boot 3 全部迁到 `jakarta.*`；
- Redis 6 之前单线程模型，6.0 引入 IO 多线程，但命令执行仍是单线程；
- Kafka 3.x 逐步移除 ZooKeeper 依赖，KRaft 成为默认方向。

如果不声明基线，读者会拿着 JDK 8 的经验去排查 JDK 21 的问题，或者反过来。所以本库统一约定：**文章正文默认按下面的基线讲解；涉及版本差异时，必须在文中标注版本。**

## 二、统一版本基线

| 领域 | 基线版本 | 说明 |
|---|---|---|
| JDK | **JDK 25 LTS**（必要时提 JDK 26/27） | 语言新特性覆盖 8-25；虚拟线程、Record、Sealed、Stream Gatherers 以 25 为准；JDK 21 仍是最常见生产版本，差异会在文中标注 |
| Spring | **Spring Boot 4.x / Spring Framework 7.x** | Boot 4.0 于 2025-11 GA（Java 17 基线、一等公民支持 Java 25、JSpecify 空安全、模块化拆分、Jackson 3 / JUnit 6）；Spring Cloud 2025.1.0（Oakwood）基于 Boot 4 |
| 持久层 | MyBatis 3.5.x、Hibernate 7.x | JPA 文章按 Jakarta Persistence 3.2 讲；Hibernate 7 与 Boot 4 配套 |
| MySQL | **MySQL 8.0 / 8.4 LTS** | 默认隔离级别 RR、`utf8mb4`、窗口函数、`INSTANT` DDL 按 8.x；8.4 为 LTS，9.x 属创新版，结论需标注 |
| PostgreSQL | PostgreSQL 17 | MVCC、VACUUM、逻辑复制、分区表按 17 讲；18 的新特性单独标注 |
| Redis | Redis 8.x | 集群、持久化、`GEOSEARCH`、Function、新数据结构按 8.x 讲；7.x 差异标注 |
| 消息队列 | Kafka 4.x（KRaft only）、RocketMQ 5.x、RabbitMQ 4.x | Kafka 4.0 起不再支持 ZooKeeper，默认 KRaft、KIP-848 新消费组协议；Quorum Queue 与经典镜像队列差异单独标注 |
| 搜索引擎 | Elasticsearch 8.x（9.x 迁移期） | 向量检索、Java API Client 按 8.x 讲；升级到 9.x 的字段类型与客户端变化需对照官方升级指南 |
| 容器 | **Kubernetes 1.36+** | 1.30 已停止维护、1.34 于 2026-10 EOL；CNI、Gateway API、HPA、Operator 按当前受支持版本讲，API 版本差异必须标注 |
| 可观测性 | OpenTelemetry 1.x、Prometheus 3.x、Grafana 11+ | 语义约定（semconv）随版本变化，文中会注明 |
| 大数据 | Hadoop 3.x、Spark 4.x、Flink 2.x、Hive 3.x | Spark 4.0 于 2025-05 发布（Spark Connect、VARIANT 类型）；Flink 2.0 于 2025-03 发布（分离式状态、物化表）；Iceberg 1.x、Hudi 1.x、Paimon 1.x；Doris 3.x、StarRocks 3.x、ClickHouse 25.x |
| AI | Spring AI 1.x、LangChain4j 1.x | 模型 API 与向量库 SDK 迭代快，以官方文档为准 |

> 基线不是「唯一正确版本」。如果你的生产环境是 JDK 17 + Boot 2.7，读文章时要主动做版本映射，尤其是 `javax/jakarta`、默认 GC、默认隔离级别、K8s API 版本这些差异点。

## 三、源码引用规范

本库强调「源码级实证」，但源码会随版本演进。引用时遵循：

1. **优先给类名 + 方法名**，例如 `HashMap.putVal`、`DispatcherServlet.doDispatch`，而不是只给行号。
2. 必须给行号时，说明是哪个版本、哪个仓库；行号只作定位参考，不作为唯一依据。
3. 不给「某行代码一定在 1234 行」这类易失效断言；需要时写成「在 `resize()` 中可以看到……」。
4. 参数默认值、阈值、常量，标注版本；无法确认时写「以实际版本为准」，不硬编。
5. 外部链接优先官方文档、JEP、RFC；不引用二手博客作为唯一依据。

## 四、内容更新策略

- **每半年**对照各组件 LTS/大版本，检查一次基线与「过时结论」。
- 大版本升级（如 JDK 21→25、Boot 3→4、K8s 1.30→1.33）时，优先更新：语言新特性、Spring 启动/自动配置、K8s 网络与 API、消息队列默认行为。
- 默认值、阈值、性能数字属于「高漂移内容」，更新时优先核对。
- 方法论、架构模式、系统设计类内容漂移慢，但仍需补充新案例与新约束（如 AI 成本、合规要求）。
- 新增文章必须写清结论适用的版本与默认值口径（正文内直接标注，不单列参考资料）。

### 高漂移内容清单（每次复核优先查）

- **默认值**：JVM 默认收集器与堆参数、MySQL 默认隔离级别与 `innodb_*`、Redis 持久化与 maxmemory 策略、Kafka 默认分区/副本/`acks`、Flink checkpoint 间隔。
- **自动配置与配置键**：Boot 3→4 的 `spring.*` 键改名、starter 模块拆分、`@ConfigurationProperties` 前缀。
- **API 版本**：K8s 各 API 组（`apps/v1`、`networking.k8s.io/v1`）、Gateway API、ES Java Client。
- **协议默认行为**：Kafka KRaft、HTTP/3 的 QUIC 支持、TLS 1.3 套件、JDK 虚拟线程的 pinning 修复（JEP 491）。
- **性能数字**：文章里出现的 QPS、延迟、GC 停顿、Shuffle 数据量，一律视为「量级参考」，不作为承诺值。

### 复核机制

- 每年 **4 月 / 10 月**各做一次基线复核，对应 Spring 与 JDK 的发布节奏；
- 每次复核开一个 Issue，标题格式 `[基线复核] YYYY-MM`，正文直接贴上面的高漂移清单逐项打勾；
- 大版本升级（如 JDK 25→29、Boot 4→5）只优先改「语言新特性、启动/自动配置、K8s 网络、消息队列默认行为」四类篇目，其余按 Issue 排期。
