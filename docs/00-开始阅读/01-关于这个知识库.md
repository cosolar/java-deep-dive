# 关于这个知识库

> 定位：一套面向 Java 高级工程师 / 架构师的系统性知识体系，共 20 大板块、167 篇深度文章。目标是让你「懂原理、知坑、会调优、能做选型、能排查线上问题」——外加「架构师实战面试」场景题库、「软件开发方法论」体系、「AI 工程化」前沿和「Java 大数据」体系。

## 这不是什么

先说清楚边界，帮你判断这套内容适不适合你：

- **不是零基础入门教程**。默认你已经会用 Java、Spring、MySQL，写过项目。这里讲的是「为什么」和「怎么在生产环境用稳」。
- **不是面试八股背诵手册**。虽然每篇都有「面试高频」一节，但答案建立在理解之上，不是让你背模板。
- **不是 API 调用文档**。官方 API 请查官网，这里讲的是机制、坑、取舍。

## 这是什么

一套按**架构师能力模型**组织的知识体系。它从七个维度展开：

1. **语言与底层**：Java 语言核心（集合源码/String/泛型/反射/异常/新特性）、JVM 与并发、Linux 与网络（含 HTTP/TLS/Nginx）
2. **框架**：Spring 体系源码（含 MVC、Boot、WebFlux）、MyBatis 与持久层（含连接池、JPA）
3. **数据与中间件**：数据库（MySQL/PostgreSQL/NoSQL/NewSQL）、缓存与中间件（Redis/MQ/ES/ZK）
4. **大数据与实时计算**：HDFS/MapReduce、Hive/Spark、Flink、实时数仓、OLAP、数据湖、数据治理
5. **分布式与架构**：分布式理论（含共识算法）、微服务、架构设计、典型系统设计（秒杀/支付/IM/订单/搜索等）
6. **工程与稳定性**：高可用、可观测性、云原生、安全、项目治理
7. **方法论与前沿**：软件开发方法论、AI 与 LLM 工程化、架构师实战面试

覆盖完整范畴：Java 语言核心、JVM 并发、Linux 网络、Spring、MyBatis、数据库（含 NoSQL/NewSQL/PostgreSQL）、中间件（含 RabbitMQ）、大数据（Hadoop/Spark/Flink/OLAP/数据湖）、分布式共识、微服务、架构设计与系统设计、高可用、可观测性、云原生、安全、项目治理、开发方法论、AI 工程化、面试实战。

> 三个层面别混：**开发方法论**（团队怎么协作、怎么交付）> **架构模式**（系统怎么搭）> **设计模式**（代码怎么写）。缺了方法论这一层，架构师的方案再优雅也可能死在「推不动、落不了地」。

## 每篇文章的结构

为了让知识可检索、可复习，每篇都遵循统一结构：

| 章节 | 你能在里面得到什么 |
|---|---|
| 一句话定位 | 30 秒判断这篇是否值得读 |
| 背景 / 为什么 | 从真实痛点切入，建立问题意识 |
| 核心原理 | 主体内容 + Mermaid 原理图 |

| 生产坑点与排查 | 「现象 → 原因 → 解法」的真实案例 |
| 调优 / 选型 / 最佳实践 | 可落地的清单和决策表 |
| 面试高频问法 | 高频问题 + 答题要点 |
| 小结 | 3-5 条速记 |

## 架构师实战面试板块（第 20 板块）

前面板块的「面试高频」是**知识点题**——考你知不知道。但架构师面试真正问的是**场景题**：你做过什么、怎么决策、踩过什么坑、会不会权衡。第 20 板块就是为这个而设。

每一道题都是一个完整的面试现场：

| 环节 | 内容 |
|---|---|
| 真实问法 | 带数字和约束的高阶提问，不是「什么是 X」 |
| 考察什么 | 面试官想验证的能力（决策/权衡/量化/复盘/推动） |
| 答题骨架 | 按 STAR-L 组织，并有 Mermaid 图讲清方案 |
| 公开案例 | 引用大厂技术博客/大会演讲/官方文档的真实实践，标注来源 |
| 追问链 | 面试官会怎么层层深挖，你怎么接 |
| 翻车点 | 哪些话一说出口就减分 |
| 调用知识 | 回扣前面 12 板块对应篇目做原理支撑 |

> **重要**：这套题库不教你编造经历。答题骨架是让你填入**自己真实项目**的框架；公开案例都标注了来源。没做过就坦诚说没做过，用清晰的决策链证明判断力——这比心虚的编造强一百倍。建议先读该板块的《架构师面试的底层逻辑》。

## 软件开发方法论板块（第 17 板块）

前面板块讲「代码怎么写、系统怎么搭」，第 17 板块讲「软件是怎么被开发出来的」——团队用什么流程、什么节奏、什么协作方式。这是架构师最容易忽略、却最影响落地成败的一层。

12 篇覆盖完整的开发方法论谱系：

| 主题 | 篇目 |
|---|---|
| 全景与选型 | 生命周期与模式全景（瀑布/迭代/敏捷怎么选） |
| 预测型流程 | 瀑布、V 模型、螺旋模型 |
| 敏捷核心 | 敏捷宣言、12 原则、和瀑布的本质区别 |
| 落地框架 | Scrum（三角色五事件三工件）、Kanban（限 WIP）、XP（TDD/结对/CI） |
| 精益与 MVP | 精益创业、最小可行产品、Build-Measure-Learn |
| 规模化 | SAFe、LeSS、Spotify 模型 |
| 交付工程 | DevOps、持续交付、DORA 四指标 |
| 需求与度量 | 用户故事、故事点、Planning Poker、燃尽图 |
| 落地实践 | 十大反模式、架构师在敏捷中的角色 |

> 一个提醒：**敏捷 ≠ 快，MVP ≠ 半成品，Scrum ≠ 敏捷**。这套内容不吹捧任何方法论，而是讲清「每种方法解决什么问题、什么情况不该用、怎么落地不翻车」。

## Java 语言核心与持久层（第 01、05 板块）

前面板块偏「运行时和分布式」，这两个板块补的是**语言本身和日常开发主干**——面试最高频、代码天天用的部分。

**第 01 板块 Java 语言核心（7 篇）**：

| 篇目 | 讲什么 |
|---|---|
| 集合框架源码 | HashMap 的 2 的幂/0.75/树化阈值、JDK7 死循环、CHM 从分段锁到 CAS |
| 集合体系补全 | ArrayList 扩容与 fail-fast、LinkedList 与 Deque、TreeMap 红黑树、集合选型 |
| String 与字符串池 | 不可变性、Compact Strings、常量池与 intern、拼接性能、编码与乱码 |
| 泛型与类型擦除 | 擦除、桥方法、PECS、为什么不能 `new T()` |
| 反射注解与动态代理 | `Method.invoke` 的 inflation、注解三档 Retention、JDK Proxy vs CGLIB |
| 异常体系与日志规范 | 受检/非受检、try-with-resources、异常表、日志级别/MDC/脱敏 |
| Java 8-21 新特性 | Stream 惰性求值、Optional、Records、Sealed、虚拟线程 |

**第 05 板块 MyBatis 与持久层（5 篇）**：

| 篇目 | 讲什么 |
|---|---|
| 架构与执行流程 | 四大组件、`selectOne` 完整链路、MapperProxy、Executor 体系 |
| 缓存与插件 | 一级/二级缓存失效条件、缓存装饰器链、插件拦截四大对象 |

> 这两块和已有内容咬合：设计模式篇讲的 `MapperProxy`（代理模式）、缓存装饰器链（装饰器模式），在这里展开成完整原理；AQS 篇讲的并发容器，正好接上集合源码篇。

## Linux 网络、系统设计与 AI 工程化（第 03、11、18 板块）

这三个板块补的是「架构师的能力边界」——往下扎到操作系统，往横扩到系统设计，往前看到 AI 时代。

**第 03 板块 Linux 与网络（6 篇）**：Java 服务跑在 Linux 上，CPU 飙高、连接堆积最终都要落到 OS 层。覆盖 USE 排查方法、CPU/内存/磁盘/网络四大子系统的命令与指标、TCP 三次握手/四次挥手/TIME_WAIT/拥塞控制、epoll 红黑树与 LT/ET；应用层补齐 HTTP/1.1→HTTP/2→HTTP/3、HTTPS/TLS 握手与证书、Nginx 与四七层负载均衡。

**第 11 板块 典型系统设计（10 篇）**：架构师面试的「系统设计题」核心，每篇按「需求 → 挑战 → 架构 → 细节 → 坑点」讲透：

| 篇目 | 核心考点 |
|---|---|
| 秒杀 | 分层过滤、Redis 预扣、超卖与少卖的取舍 |
| 支付 | 幂等、对账、资金安全、状态机 |
| IM | 长连接、消息可靠与顺序、写扩散 vs 读扩散 |
| 短链与 Feed | 62 进制发号、推拉结合 |
| 订单与库存 | 状态机、预占/回补、防超卖、对账、逆向退款 |
| 营销优惠券与风控 | 券生命周期、防超发、规则引擎、误杀与人工审核 |
| 搜索系统 | 倒排索引、BM25、召回/排序、索引同步、深翻页 |
| 消息推送与长连接网关 | 多通道、连接路由、离线消息、推送风暴 |
| 对象存储与音视频 | 分片上传、秒传、CDN、转码、HLS、鉴权 |
| LBS 与打车 | GeoHash、派单匹配、轨迹、围栏、隐私 |

**第 18 板块 AI 与 LLM 工程化（6 篇）**：从「调 API」到「工程落地」。RAG 双链路（切分/Embedding/HNSW/混合检索/Rerank）、Agent 与 Function Calling/ReAct/MCP、企业级 LLM 应用架构（多模型路由/成本控制/Prompt 注入防护）、RAG 进阶与评估、Prompt 工程与 AI 应用评测、向量数据库与模型部署。

## Java 大数据板块（第 19 板块）

大数据不是「另一个世界」——Hadoop、Spark、Flink、Kafka、Hive 全是 JVM 生态，Java 工程师转大数据有天然优势。这个板块不写运维手册，而是从**Java 视角**讲原理、选型与生产坑：

| 篇目 | 核心内容 |
|---|---|
| 技术全景 | 存储/计算/查询/消息/调度/数据湖全景、批流与实时数仓、选型决策树 |
| HDFS 与 MapReduce | NameNode/DataNode、块与副本、读写流程、shuffle、YARN |
| Hive 与 Spark SQL | Metastore、分区/分桶、ORC/Parquet、数仓分层、Catalyst |
| Spark 核心与调优 | RDD/Stage/Shuffle、统一内存、AQE、数据倾斜六解法 |
| Flink 流计算 | 事件时间/水位线、状态后端、Checkpoint、Exactly-Once、反压 |
| Kafka 与实时数仓 | EOS、CDC/Debezium、ODS→ADS 链路、积压治理 |
| OLAP 选型 | ClickHouse/Doris/StarRocks 的引擎、更新能力与选型 |
| 数据湖与湖仓一体 | Iceberg/Hudi/Paimon、快照与时间旅行、小文件合并 |
| 数据治理与质量 | 元数据/血缘、质量规则、稽核、SLA、成本治理 |

> 建议先读《Java 大数据技术全景》建立地图，再按「存储 → 计算 → 实时链路 → OLAP → 治理」推进；每篇都标注了与已有 Kafka、数据库、可观测性文章的衔接点。
