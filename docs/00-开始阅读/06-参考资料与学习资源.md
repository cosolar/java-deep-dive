# 参考资料与学习资源

> 定位：一套可长期使用的「查证入口」。文章里的结论会随版本变化，真正可靠的是官方文档、规范、源码和经典书。这一页按板块整理优先阅读的一手资料，遇到争议先回到这里核对，而不是继续搜二手博客。

## 一、怎么用这份清单

1. **先官方、后社区**。官方文档与规范是唯一权威；博客、视频只用来建立直觉，不作为结论依据。
2. **带版本查**。同一个问题在 JDK 8 与 21、Boot 2 与 3、MySQL 5.7 与 8.0 下答案可能不同，先确认版本再查文档。
3. **源码优先于转述**。框架类问题直接看入口类和调用链，比看十篇解析更可靠。
4. **读书用来补体系**。经典书的价值是把零散知识串成结构，不是替代官方文档。

## 十、查证与提问的方法

- **先定位版本**：`java -version`、`mvn dependency:tree`、`SELECT VERSION()`、`kubectl version`，版本不对，结论可能全反。
- **再找入口**：框架问题从入口类开始（`DispatcherServlet`、`MapperProxy`、`KafkaConsumer.poll`），顺着调用栈读，不要一上来啃全部源码。
- **区分三类结论**：协议/规范（稳定）、实现细节（随版本）、经验值（随场景）。文章里也要按这三类表述。
- **遇到分歧看测试**：源码注释、单元测试、官方 issue 往往比博客更接近事实。
- **记录依据**：做技术决策时，把版本、文档章节、压测数据一起记录下来，方便半年后复盘。

## 小结

- 一手资料优先级：官方文档/规范 > 源码与测试 > 经典书 > 社区文章。
- 查任何结论前先确认版本；默认值、阈值、API 签名都属于高漂移信息。
- 大数据与 AI 的资料更新最快，优先看官方 Release Notes 与论文原文。
- 读书补体系，文档查细节，源码定事实，压测做决策。
